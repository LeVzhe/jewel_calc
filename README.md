# jewel_calc

Домашний калькулятор бижутерии. Сейчас готов каталог комплектующих: API на FastAPI и PostgreSQL в Docker. Фронтенд будет отдельной папкой `frontend` и подключится к тому же `run.sh`.

Приложение для своих. Отдельной авторизации нет. Записи не удаляются физически: их архивируют и при необходимости возвращают.

## Стек

- Python 3.12, FastAPI, Pydantic, SQLAlchemy 2, Alembic
- PostgreSQL 16
- Poetry и локальное виртуальное окружение `backend/.venv`
- Картинки в Cloudflare R2, клиент `aioboto3`
- Docker Compose: сервисы `api` и `db`

Слои API такие же, как в foodbox: `controllers` → `services` → `repositories` → `models`.

## Каталог

У каждой записи есть числовой `id`, `guid` (uuid4), `created_at`, `updated_at` и флаг `is_archived`.

### Тип комплектующего

Три корня создаёт миграция, их имена фиксированы:

- Фурнитура
- Упаковка
- Нить

Новый тип — прямой потомок одного из корней. Комплектующее можно повесить и на корень, и на подтип. Корень нельзя переименовать и нельзя заархивировать. Подтип нельзя заархивировать, пока на него ссылается неархивное комплектующее.

### Цвет

Отдельный справочник. Цвет необязателен: фото остаётся главным. Миграция сразу кладёт: серебро, золото, розовое золото, античное серебро, античное золото, медь, бронза, чёрный, белый, прозрачный. Свои цвета добавляются через API. Цвет нельзя заархивировать, пока его используют живые комплектующие.

### Комплектующее

| Поле | Смысл |
| --- | --- |
| `name` | Название в каталоге. Внутри одного типа активные имена не повторяются без учёта регистра |
| `cost` | Цена за одну единицу, число с двумя знаками после запятой, не меньше нуля |
| `unit` | За что эта цена: `шт`, `м`, `см`, `г`, `упаковка`. По умолчанию `шт` |
| `article` | Артикул, можно не указывать |
| `type_id` | Тип |
| `color_id` | Цвет или `null` |
| `shops` | Список строк: где покупали и где можно купить. Пустой список очищает пометки |
| `image`, `image_preview` | Публичные URL фото и превью |

`unit` нужен будущему расчёту изделия. Тросик за 80 ₽ с единицей `м` и расходом 0,2 м даёт 16 ₽. Замок за 25 ₽ с единицей `шт` и одной штукой даёт 25 ₽. Без единицы цена была бы просто числом, и калькулятор не знал бы, на что её умножать.

Размер пока живёт в названии. Отдельные остаток, заметка и размер в каталог не входят: их можно добавить миграцией позже.

Имена сравниваются по внутреннему ключу в нижнем регистре, чтобы «Карабин» и «карабин» не стали двумя активными позициями. Поиск по списку тоже не зависит от регистра.

## Картинки

Фронту достаточно полей `image` и `image_preview`: это обычные `https://...` ссылки для `<img src>`. Ключи R2 наружу не отдаются.

При создании и замене клиент присылает `image_base64`. Подойдёт чистый base64 или строка `data:image/jpeg;base64,...`. Перед загрузкой сервер приводит кадр к одному виду: ориентация по EXIF, цвет в sRGB, квадрат с белым полем и полями 6%. Полное фото — 1200×1200, превью — 400×400. Маленький кадр не растягивается, цвет металла не выравнивается автоматически. Файлы кладутся в бакет:

```text
jewel_calc/components/<guid>/<guid>_image.jpg
jewel_calc/components/<guid>/<guid>_preview.jpg
```

Можно использовать тот же бакет и те же ключи, что в foodbox: префикс папки другой. При архивации файлы остаются, чтобы карточку можно было вернуть. Новая картинка при правке пишется по тому же `guid` и заменяет старую.

Лимит исходника — 10 МБ.

## Запуск в Docker

Снаружи приложение слушает тихие порты, чтобы не пересекаться с другими локальными сервисами.

1. Скопируй `backend/.env.example` в `backend/.env`.
2. Заполни `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ACCOUNT_ID`, `R2_BUCKET_NAME`, `R2_PUBLIC_BASE_URL`.
3. Из корня репозитория:

```bash
bash run.sh
```

API: <http://localhost:47221>  
Документация: <http://localhost:47221/docs>  
Проверка: <http://localhost:47221/health>  
Postgres с хоста: `localhost:47232`, база `jewel_calc`, пользователь и пароль `jewel`.

Внутри сети compose API ходит в базу как `db:5432`, а сам процесс слушает `8000`. Эти порты с компьютера не видны. В `.env` хост `localhost` и порт `47232` нужны, если API запускаешь на хосте, а база в контейнере.

Другие команды:

```bash
bash run.sh up --build -d   # в фоне
bash run.sh logs -f api
bash run.sh down            # остановить, данные Postgres сохраняются
```

При старте контейнер сам выполняет `alembic upgrade head`. Процесс API внутри контейнера — `fastapi run`, без автоперезагрузки: после правки кода контейнер нужно перезапустить. Для перезагрузки на лету удобнее локальный `fastapi dev` из раздела ниже. Первый запуск собирает образ и ставит зависимости, нужен доступ в сеть.

## Локальное окружение

Из папки `backend`, когда база уже поднята:

```bash
poetry lock
poetry install
poetry run alembic upgrade head
poetry run fastapi dev app/main.py --host 127.0.0.1 --port 47221
```

Poetry создаёт `backend/.venv` (`poetry.toml`, `in-project = true`). В Docker зависимости ставятся в системный Python образа, без venv.

Пока в репозитории нет `poetry.lock`: его создаёт `poetry lock` локально или первая сборка образа.

## API

Списки по умолчанию скрывают архив. Параметр `include_archived=true` показывает его. Пагинация: `skip` (с 0) и `limit` (по умолчанию 50, максимум 200).

У комплектующих дополнительно: `type_id` (точное совпадение), `color_id`, `search` по названию.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/component-type/list` | Типы, корни сверху |
| POST | `/component-type/create` | Подтип: `name`, `parent_id` |
| GET | `/component-type/{id}` | Один тип |
| PATCH | `/component-type/{id}` | Новое имя подтипа |
| PATCH | `/component-type/archive` | `{"ids":[1,2]}` |
| PATCH | `/component-type/unarchive` | Вернуть из архива |
| GET | `/color/list` | Цвета |
| POST | `/color/create` | `{"name":"Бордо"}` |
| GET/PATCH | `/color/{id}` | Карточка и переименование |
| PATCH | `/color/archive`, `/color/unarchive` | Архив |
| GET | `/component/list` | Каталог |
| POST | `/component/create` | Новая позиция и фото |
| GET/PATCH | `/component/{id}` | Карточка и правка |
| PATCH | `/component/archive`, `/component/unarchive` | Архив |

Ответ архивации:

```json
{"ids": [4], "skipped": [{"id": 1, "reason": "system type"}]}
```

`ids` — что изменилось. `skipped.reason`: `not found`, `already archived`, `already active`, `system type`, `used by active components`, `type is archived`, `name already used`.

Пример создания:

```json
{
  "name": "Карабин лобстер",
  "cost": 25.5,
  "unit": "шт",
  "type_id": 1,
  "color_id": 1,
  "article": "LB-12",
  "shops": ["Ozon", "WB, дешевле набором"],
  "image_base64": "<base64>"
}
```

В ответе будут вложенные `type` и `color` и список `shops`. `type_id` корня «Фурнитура» после чистой миграции обычно `1`, но ориентироваться лучше на `GET /component-type/list`.
